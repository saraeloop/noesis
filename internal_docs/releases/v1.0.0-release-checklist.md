# Noēsis v1.0.0 Release Checklist

This is the **minimal ritual** before tagging `v1.0.0`.  
Everything else (SBOMs, OTLP, policy audits, fancy TUI) is 1.1+.

---

## 0. ADRs & Roadmap

- [ ] **ADR-001 — Runtime Session**
  - [ ] ADR-001 marked **Accepted** (not Proposed) and matches current code.
  - [ ] `NoesisSession` / `SessionBuilder` behavior in docs is consistent with the implementation.
- [ ] **ADR-002 / ADR-003 / ADR-004**
  - [ ] ADR text reflects the actual implementation (canonical serialization, determinism primitives, artifact layout).
  - [ ] ADR-004 clearly distinguishes:
    - **substrate** (canonical serialization + determinism plumbing),
    - **drill** (replay comparator + golden),
    - ADR-006 (future drift tooling).
- [ ] **ADR-005 — Prompt Provenance**
  - [ ] Either clearly marked **Proposed / Experimental** (if not shipped),  
  - [ ] Or documented as **v0.1, optional & behind feature flag** (if partially implemented).

---

## 1. Public interface & versioning

- [ ] Update `CHANGELOG.md` with highlights and any breaking changes.
- [ ] Bump `noesis.__version__` and any schema version constants as needed.
- [ ] Confirm no deprecated shims are importable without an explicit legacy flag.
- [ ] Sanity-check that exported modules match the documented API (README + docs).
- [ ] Run `python -m noesis` or `noesis --version` and confirm version shows `1.0.0`.

---

## 2. Determinism & artifacts (ADR-002 / ADR-004)

- [ ] Run the full test suite: `uv run python -m pytest`.
- [ ] Ensure `tests/runtime/test_determinism.py` and `tests/runtime/test_serialization.py` are green.
- [ ] Run a minimal-mode episode and a meta/governed episode; keep both run dirs.
- [ ] Run `noesis artifacts verify <episode_dir>` on each and confirm `manifest.json` passes.

### 2.1 Replay comparator (ADR-004 drill)

- [ ] **Implement replay helper**:
  - Add a small comparator (CLI or API), e.g.:
    - `noesis diagnostics replay <run_a> <run_b>`, **or**
    - a public helper like `noesis.diagnostics.compare_runs(dir_a, dir_b)`.
  - Reuse the normalization logic from `tests/runtime/test_determinism.py` to:
    - compare `summary.json` bytes,
    - normalize `state.json` / `manifest.json`,
    - structurally compare `events.jsonl`.
- [ ] **Wire a deterministic golden**:
  - Add a tiny scenario that runs twice under `DeterminismConfig`,
  - Store both run dirs somewhere under `tests/golden/` (e.g. `tests/golden/determinism/`),
  - Assert the comparator reports **NO DRIFT** in CI.

### 2.2 Manual sanity

- [ ] Use the replay comparator on a deterministic scenario:
  - [ ] `noesis diagnostics replay <run_a> <run_b>` (or equivalent),
  - [ ] Confirm it reports **NO DRIFT** for summary/state/manifest/events.
- [ ] Manually inspect one `events.jsonl` + `state.json` to verify phases, lineage, and IDs look sane.

---

## 3. NoesisSession GA (ADR-001)

- [ ] `SessionBuilder(...).build()` → `NoesisSession.run/solve` flows are documented and stable.
- [ ] Tests cover:
  - [ ] Two independent sessions don’t leak state into each other.
  - [ ] A deterministic run vs. a non-deterministic run behaves as expected (artifacts only match when `DeterminismConfig` is on).
- [ ] README / docs include a short “How to use `NoesisSession`” section:
  - [ ] Basic example with `SessionBuilder`.
  - [ ] Optional `with_determinism(...)` usage.

---

## 4. Prompt Provenance v0.1 (Optional)

- [ ] `prompt_provenance_enabled` feature flag exists and defaults are sane.
- [ ] When enabled, `prompts.jsonl` is created with at least:
  - [ ] `episode_id`, `phase`, `agent_id`, `rendered`, `fingerprint`, `timestamp`, `model`, `mode`.
- [ ] A small deterministic test confirms `prompts.jsonl` is identical across two runs under `DeterminismConfig`  
  _or_ the feature is documented as disabled in deterministic mode for 1.0.
- [ ] Docs clearly mark prompt provenance as **experimental** and **optional**.

---

## 5. CLI & configuration sanity

- [ ] `noesis run "Hello"` works from a clean venv.
- [ ] `noesis view <episode_dir>` shows a readable summary (even if plain).
- [ ] Flip planner mode via `NOESIS_PLANNER` and/or `ns.set(planner_mode=...)`; confirm minimal vs meta behavior.
- [ ] Smoke-test:
  - [ ] `noesis migrate` (if present),
  - [ ] `noesis diagnostics` (including the replay/compare command).
- [ ] Confirm CLI help (`noesis --help`) lists only supported, non-stale commands.

---

## 6. Packaging

- [ ] Build wheels: `uv build` (or your chosen builder).
- [ ] Create a clean venv, `pip install dist/noesis-*.whl` and confirm:
  - [ ] `python -c "import noesis"` works.
  - [ ] `noesis --help` works.
- [ ] Tag the release:
  - [ ] `git tag -s v1.0.0 -m "Noēsis v1.0.0"`
  - [ ] `git push --tags`
- [ ] Draft GitHub release with:
  - [ ] Link to `CHANGELOG.md` v1.0.0 entry.
  - [ ] Short “what’s in v1.0.0” summary.
  - [ ] Call-out for determinism/replay + artifacts.
