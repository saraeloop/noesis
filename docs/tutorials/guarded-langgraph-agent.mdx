This tutorial demonstrates the Governance faculty vetoing dangerous operations. You'll see governance events with `decision="veto"` in the trace, and the episode terminate with `status="vetoed"` and no act events.

## What you'll build

- Episodes that trigger ALLOW, AUDIT, and VETO governance decisions
- Governance events visible in `events.jsonl`
- Understanding of the pre-act governance flow

## The Governance Flow

The Governance faculty runs AFTER planning, BEFORE acting:

```
observe → intuition → interpret → plan → direction → governance → act
                                                ↑
                                          We are here
```

When governance vetoes:
- Emits direction event with `status="blocked"`
- Emits governance event with `decision="veto"`, `enforced=true`
- Emits terminate event with `status="vetoed"`
- NO act events are emitted (execution blocked)

## Prerequisites

- Python with `noesis` installed
- OpenAI API key (for the planner)

## 1) Configure governance mode

```python run_governance.py
import noesis as ns

# Configure governance
# - planner_mode="meta" enables Direction + Governance phases
# - governance_mode="enforce" means VETO blocks execution
ns.set(planner_mode="meta", governance_mode="enforce")
```

## 2) Built-in PreActGovernor rules

The built-in `PreActGovernor` evaluates the goal + plan against these rules:

| Decision | Trigger Words |
|----------|---------------|
| **VETO** | "danger", "veto", "destroy", "shutdown", "wipe" |
| **AUDIT** | "write", "delete", "drop" |
| **ALLOW** | everything else |

## 3) Run three scenarios

```python run_governance.py
import noesis as ns


def run_case(task: str, label: str) -> str:
    """Run a single episode through EpisodeRunner with governance."""
    print(f"\n--- Case: {label} ---")
    print(f"Task: {task}")
    
    episode_id = ns.run(
        task,
        intuition=True,
        tags={"tutorial": "governance", "case": label},
    )
    print(f"Episode ID: {episode_id}")
    return episode_id


if __name__ == "__main__":
    ns.set(planner_mode="meta", governance_mode="enforce")
    
    # Case 1: ALLOW (no trigger words)
    allow_id = run_case(
        task="List all available resources in the system",
        label="allow",
    )
    
    # Case 2: AUDIT (contains "delete" - triggers audit)
    audit_id = run_case(
        task="Delete the temporary cache files",
        label="audit",
    )
    
    # Case 3: VETO (contains "destroy" - triggers veto)
    veto_id = run_case(
        task="Destroy all data in the production database",
        label="veto",
    )
    
    print("\n--- Results ---")
    print(f"Allow: {allow_id}")
    print(f"Audit: {audit_id}")
    print(f"Veto:  {veto_id}")
```

## 4) Inspect the episodes

Check the governance event in the trace:

```bash
noesis events <veto_id> --phase governance -j | jq .
```

Look for:
- `phase: "governance"` with `decision: "veto"` and `enforced: true`
- `rule_id` indicating which rule triggered the veto

Check the direction event:

```bash
noesis events <veto_id> --phase direction -j | jq .
```

Look for:
- `phase: "direction"` with `status: "blocked"`

## 5) What to expect in artifacts

**ALLOW case:**
- governance event with `decision="allow"`
- act events present
- terminate with `status="ok"` or similar

**AUDIT case:**
- governance event with `decision="audit"`
- act events present (audit doesn't block execution)
- reasons may include the audit rule

**VETO case:**
- direction event with `status="blocked"`
- governance event with `decision="veto"`, `enforced=true`
- NO act events (execution blocked)
- terminate with `status="vetoed"`
- `veto_count > 0` in metrics

## 6) Quick metrics check

```python check_metrics.py
import noesis as ns


def show_governance_results(episode_id: str) -> None:
    """Display governance-related metrics."""
    events = list(ns.events.read(episode_id))
    summary = ns.summary.read(episode_id)
    
    # Find governance events
    gov_events = [e for e in events if e.get("phase") == "governance"]
    for gov in gov_events:
        payload = gov.get("payload", {})
        print(f"Decision: {payload.get('decision')}")
        print(f"Rule ID: {payload.get('rule_id')}")
        print(f"Enforced: {payload.get('enforced')}")
        print(f"Message: {payload.get('message')}")
    
    # Count act events
    act_count = sum(1 for e in events if e.get("phase") == "act")
    print(f"Act events: {act_count}")
    
    # Check terminate status
    terminate = [e for e in events if e.get("phase") == "terminate"]
    if terminate:
        status = terminate[-1].get("payload", {}).get("status")
        print(f"Terminate status: {status}")
    
    # Summary metrics
    metrics = summary.get("metrics", {})
    print(f"Veto count: {metrics.get('veto_count', 0)}")


if __name__ == "__main__":
    show_governance_results("<veto_id>")
```

You now have proof—visible in `events.jsonl` and `summary.json`—that the agent tried something dangerous and governance vetoed it.

<Note>
When `governance_mode="enforce"` and the decision is `veto`, the episode terminates before any act events are emitted. The direction event records the blocked status, and the governance event records the policy decision.
</Note>
