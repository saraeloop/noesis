---
title: "Configure shared episode storage"
description: "Point Noēsis at a shared location via network volumes, S3 sync, Docker mounts, or Kubernetes PVCs."
---

By default, Noēsis writes episodes under `./.noesis/episodes/<episode-id>/`. In a team or service setting, you usually want a **shared** location so everyone can see/replay the same traces.

This guide shows four common setups:

1. Network volume (NFS/SMB)
2. Local + S3 sync
3. Docker bind mount
4. Kubernetes PersistentVolumeClaim

<Tip>
Pick one of these patterns for your environment—you don’t need all four.
</Tip>

## A) Shared dev: network volume

```bash
# Example: shared volume mounted at /srv/noesis/episodes
ls /srv/noesis/episodes
# (empty or existing runs)
```

Configure your app/runtime to use a path whose parent is `.noesis` so the resolver treats it as the episodes root:

```bash
NOESIS_RUNS_DIR=/srv/noesis/.noesis/episodes
```

Result: `/srv/noesis/.noesis/episodes/<episode-id>/` is shared across the team. There is no per-service subdirectory; group runs with `--process` / `process=`.

Pitfall: `NOESIS_RUNS_DIR=/srv/noesis/episodes` (parent not named `.noesis`) resolves to `/srv/noesis/episodes/.noesis/episodes/`.

## B) Shared dev: local + S3 (or any object store)

Don’t write directly to S3; sync a local directory.

```bash
# App writes episodes locally
NOESIS_RUNS_DIR=/var/noesis/.noesis/episodes

# Periodic sync job (cron/CI)
aws s3 sync /var/noesis/.noesis s3://my-bucket/noesis-root --delete

# Optionally pull shared episodes down
aws s3 sync s3://my-bucket/noesis-root /var/noesis/.noesis
```

Pattern: local path for fast replay/debugging, S3 as central archive.

## C) Docker: bind-mount the runs directory

```bash
mkdir -p /srv/noesis/.noesis/episodes

docker run \
  -v /srv/noesis/.noesis:/app/.noesis \
  -e NOESIS_RUNS_DIR=/app/.noesis/episodes \
  my-noesis-service:latest
```

Inside the container, Noēsis writes to `/app/.noesis/episodes/<episode-id>/`; on the host, you see `/srv/noesis/.noesis/episodes/<episode-id>/`. Mount the `.noesis` root so `processes/` and `index/` stay with the episodes.

## D) Kubernetes: PersistentVolumeClaim

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: noesis-runs-pvc
spec:
  accessModes: ["ReadWriteMany"]
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-noesis-service
spec:
  template:
    spec:
      containers:
        - name: app
          image: my-noesis-service:latest
          env:
            - name: NOESIS_RUNS_DIR
              value: /var/noesis/.noesis/episodes
          volumeMounts:
            - name: noesis-runs
              mountPath: /var/noesis/.noesis
      volumes:
        - name: noesis-runs
          persistentVolumeClaim:
            claimName: noesis-runs-pvc
```

Each pod writes episodes under `/var/noesis/.noesis/episodes/<episode-id>/`, backed by the shared PVC.
