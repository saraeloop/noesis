---
title: "Configure shared episode storage"
description: "Point Noēsis at a shared location via network volumes, S3 sync, Docker mounts, or Kubernetes PVCs."
---

By default, Noēsis writes episodes under `./.noesis/episodes/<episode-id>/`. In a team or service setting, you usually want a **shared** location so everyone can see/replay the same traces.

This guide shows four common setups:

1. Network volume (NFS/SMB)
2. Local + S3 sync
3. Docker bind mount
4. Kubernetes PersistentVolumeClaim

<Tip>
Pick one of these patterns for your environment—you don’t need all four.
</Tip>

<Warning>
`runs_dir` is treated as the episodes root only when its parent is named `.noesis` (for example `/srv/noesis/.noesis/episodes`) or when `runs_dir` itself is `.noesis`. A path like `/srv/noesis/episodes` resolves to `/srv/noesis/episodes/.noesis/episodes`.
</Warning>

## A) Shared dev: network volume

```bash
# Shared volume whose parent directory is named .noesis
ls /srv/noesis/.noesis/episodes
```

```bash
NOESIS_RUNS_DIR=/srv/noesis/.noesis/episodes
```

Result: `/srv/noesis/.noesis/episodes/<episode-id>/` is shared across the team.

## B) Shared dev: local + S3 (or any object store)

Don’t write directly to S3; sync a local directory that satisfies the `.noesis` parent rule.

```bash
NOESIS_RUNS_DIR=/var/noesis/.noesis/episodes

aws s3 sync /var/noesis/.noesis s3://my-bucket/noesis-root --delete
aws s3 sync s3://my-bucket/noesis-root /var/noesis/.noesis
```

Sync the `.noesis` root (episodes, index, processes), not only a custom folder named `episodes` whose parent is not `.noesis`.

## C) Docker: bind-mount the runs directory

```bash
mkdir -p /srv/noesis/.noesis/episodes

docker run \
  -v /srv/noesis/.noesis:/app/.noesis \
  -e NOESIS_RUNS_DIR=/app/.noesis/episodes \
  my-noesis-service:latest
```

Inside the container, Noēsis writes to `/app/.noesis/episodes/...`; on the host, you see `/srv/noesis/.noesis/episodes/...`.

## D) Kubernetes: PersistentVolumeClaim

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: noesis-runs-pvc
spec:
  accessModes: ["ReadWriteMany"]
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-noesis-service
spec:
  template:
    spec:
      containers:
        - name: app
          image: my-noesis-service:latest
          env:
            - name: NOESIS_RUNS_DIR
              value: /var/noesis/.noesis/episodes
          volumeMounts:
            - name: noesis-runs
              mountPath: /var/noesis/.noesis
      volumes:
        - name: noesis-runs
          persistentVolumeClaim:
            claimName: noesis-runs-pvc
```

Each pod writes episodes under `/var/noesis/.noesis/episodes`, backed by the shared PVC.

## Layout migration

If older trees used a different root, copy leftover `ep_*` directories (not nested `label/ep_*` trees) and process `*.json` files:

```bash
noesis migrate-layout
```

The command skips existing targets, writes `MIGRATED_FROM.json` on the resolved `.noesis` root, and does not flatten label-nested episode dirs.

## Troubleshooting

### Episodes did not land where `NOESIS_RUNS_DIR` points

Cause: parent of `runs_dir` is not `.noesis`, so the runtime created `{runs_dir}/.noesis/episodes`.

Fix: set `NOESIS_RUNS_DIR` to `.../.noesis/episodes` (or to the `.noesis` directory itself) and remount/sync that path.
