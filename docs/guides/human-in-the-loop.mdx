description: "Pause a run on governance veto, collect approval, and resume the same episode."
---

Human approval in Noēsis is a **same-run continuation**, not a second episode. The runtime pauses before the side effect, writes a checkpoint, and waits. After a reviewer decides, `ns.resume_run(...)` continues that episode ID.

Do not call `ns.interrupt()` / `ns.checkpoint()` after `ns.solve()` / `ns.run()` has already returned a sealed run. Presence of `final.json` means the run is sealed; lifecycle writes then raise `RunSealedError`.

## When to pause for approval

Use pause-on-veto when:

- The side effect is **irreversible** (deletes, deploys, financial writes)
- A policy should **block actuation** until a human reviews the trace
- You need a **single append-only history** instead of a follow-up rerun

## Canonical pattern: pause on veto, then resume

Enable enforce-mode governance and pause-on-veto **before** starting the run. Built-in danger rules (for example a goal containing `"danger"`) veto in enforce mode. The runner then emits `run.interrupt` and `run.checkpoint` and returns without `act`, `terminate`, `final.json`, or `manifest.json`.

```python
import noesis as ns


def require_approval(episode_id: str, action: str) -> bool:
    """Replace with Slack, ServiceNow, or your approval UI."""
    print(f"Approval required for {episode_id}: {action}")
    return input("Approve? (y/n): ").lower() == "y"


def checkpoint_id_from_events(episode_id: str) -> str:
    events = list(ns.events.read(episode_id))
    checkpoint = next(
        event
        for event in reversed(events)
        if event.get("phase") == "runtime" and event.get("event_type") == "run.checkpoint"
    )
    return str(checkpoint["payload"]["checkpoint_id"])


def run_with_approval(task: str, using):
    ns.set(
        governance_mode="enforce",
        governance_pause_on_veto=True,
    )

    episode_id = ns.solve(task, using=using, intuition=False)
    checkpoint_id = checkpoint_id_from_events(episode_id)

    if not require_approval(episode_id, task):
        print("Rejected; run stays paused and unsealed")
        return None

    # Same run ID. resume_run does not rewrite the goal.
    return ns.resume_run(
        episode_id,
        checkpoint_id=checkpoint_id,
        using=using,
    )
```

<Tip>
`planner_mode` is independent of this path. `planner_mode="minimal"` with `governance_mode="enforce"` and `governance_pause_on_veto=True` still pauses on an enforce veto.
</Tip>

On the paused path:

| Artifact / event | Present? |
| --- | --- |
| `action_candidate` → `governance(decision=veto)` | yes |
| `run.interrupt` → `run.checkpoint` | yes |
| `act` / `terminate` | no |
| `state.json` `outcomes.status` | `partial` (summary includes `paused at checkpoint <id>`) |
| `final.json` / `manifest.json` / `summary.json` | not yet |

`ns.list_runs()` skips directories without `summary.json`, so paused runs do not appear there. Discover them by listing `ep_*` dirs that have a `checkpoints/` folder and no `final.json`.

## Resume contract

`ns.resume_run(...)` continues the **same** episode:

- Reuses the persisted goal. There is no `task=` argument; tagging the next `ns.run(...)` with `[APPROVED]` starts a **new** episode.
- Emits `run.resume` then continues post-plan by default (no replan).
- Requires `using=` for non-minimal checkpoints, matching the adapter label stored on the checkpoint / `state.json`.
- `PreActGovernor` can veto again on continuation. Pause-on-veto may fire a second time.

Checkpoint JSON lives at:

```text
.noesis/episodes/<episode_id>/checkpoints/<checkpoint_id>/checkpoint.json
```

Fields used on resume (`checkpoint/1.0.0`): `event_offset`, `last_event_id`, `state_hash`, `artifact_manifest_hash`, optional `adapter_label`.

## Manual interrupt (unsealed runs only)

`ns.interrupt` / `ns.checkpoint` / `ns.resume` are valid on an **unsealed** run. They are the wrong tool after a completed `ns.run` / `ns.solve` that already wrote `final.json`.

```python
# Only while the run is still open (no final.json)
interrupt_id = ns.interrupt(episode_id, reason="Awaiting human approval")
checkpoint = ns.checkpoint(episode_id, caused_by=interrupt_id)
ns.resume_run(episode_id, checkpoint_id=checkpoint["checkpoint_id"], using=using)
```

`ns.resume(...)` writes `run.resume` evidence only. Use `ns.resume_run(...)` when you want execution to continue.

## Approval channels

Slack, queues, and UIs are **notification and decision** surfaces. After approve/reject, call `ns.resume_run(...)` (or leave the run paused). Do not start a follow-up `ns.run(...)` to “record the approval.”

### Slack (notify, then resume)

```python
import os
from slack_sdk import WebClient
import noesis as ns

client = WebClient(token=os.environ["SLACK_BOT_TOKEN"])


def request_approval(channel: str, episode_id: str, action: str) -> None:
    client.chat_postMessage(
        channel=channel,
        text=f"Approval required for `{episode_id}`: {action}",
    )


def on_approved(episode_id: str, checkpoint_id: str, using) -> str:
    return ns.resume_run(episode_id, checkpoint_id=checkpoint_id, using=using)
```

### Async waiter

```python
import noesis as ns


async def wait_then_resume(episode_id: str, checkpoint_id: str, using, approved: bool):
    if not approved:
        return None  # leave the run paused and unsealed
    return ns.resume_run(episode_id, checkpoint_id=checkpoint_id, using=using)
```

Rejection should leave the run paused (unsealed), not spawn a new episode.

## Troubleshooting

### `RunSealedError`

The episode already has `final.json`. Typical cause: calling `ns.interrupt` after a terminal `ns.solve`/`ns.run`, or after an enforce veto with `governance_pause_on_veto=False` (that path terminates and seals).

Fix: enable `governance_pause_on_veto=True` **before** the run that needs approval.

### `CheckpointConsistencyError`

Resume compares the checkpoint to current artifacts:

| Anchor | Failure |
| --- | --- |
| `event_offset` / `last_event_id` | `events.jsonl` prefix no longer matches |
| `state_hash` | `state.json` changed |
| `artifact_manifest_hash` | `manifest.json` appeared, disappeared, or the pre-manifest digest of `events.jsonl` / `state.json` / `summary.json` / `learn.jsonl` / `prompts.jsonl` changed |

Paused runs usually have **no** `manifest.json`. Creating one after the checkpoint, or deleting one that existed at checkpoint time, fails resume.

`caused_by` on `ns.resume` / `ns.resume_run` must be the checkpoint `last_event_id` or the latest event id.

### `ResumeAdapterRequiredError` / `ResumeAdapterMismatchError`

Pass the same `using=` graph/adapter that was persisted on the checkpoint. Omitting `using` is allowed only for minimal (`core.minimal`) runs.

### Pending run missing from `ns.list_runs()`

Expected for pause-on-veto: no `summary.json` yet. Look for `checkpoints/` and a latest `run.checkpoint` event instead.
