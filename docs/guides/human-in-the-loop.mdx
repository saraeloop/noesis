Human approval in Noēsis is a runtime lifecycle, not a post-processing step.
Pause before a side effect, checkpoint the unsealed run, record approval in the
same integration, then resume the same run ID.

<Warning>
Do not call `ns.interrupt(...)` or `ns.checkpoint(...)` after a normal
`ns.run(...)` or terminal `ns.solve(...)` has returned. Terminal runs are sealed
with `final.json` and `manifest.json`; lifecycle mutations on sealed runs raise
`RunSealedError`.
</Warning>

## When to Use Approval

Add a human gate when:

- the action is irreversible, such as deletes, deployments, or financial writes
- a policy veto should become a review queue instead of an immediate terminal failure
- a protocol adapter prepares durable tool intent that must be approved elsewhere
- regulations require an auditable approver, reason, and reviewed payload binding

## Runtime Contract

The same-run lifecycle is:

```text
running -> run.interrupt -> run.checkpoint -> approval -> run.resume -> act -> terminate
```

Key properties:

- `interrupt` emits a runtime `run.interrupt` event.
- `checkpoint` writes `checkpoints/<checkpoint_id>/checkpoint.json` and emits `run.checkpoint`.
- `resume` emits lifecycle evidence only; it does not continue execution.
- `resume_run` emits `run.resume` and continues the existing run ID.
- `resume_run(..., using=...)` must match the adapter captured in the checkpoint for non-minimal runs.

## Choose a Pause Mechanism

| Mechanism | Use when | Notes |
| --- | --- | --- |
| Governed side effects | You use `ns.governed_act(...)` or governance-enforced `ns.solve(...)` for high-risk actions | Set `governance_mode="enforce"` and `governance_pause_on_veto=True`; vetoes emit `run.interrupt -> run.checkpoint` and skip `act`. |
| Protocol-first tool invocation | You are building an adapter around prepared tool intent | Use `prepare_tool_invocation(...)`, persist approval with the same `run_id + draft_id`, then call `ns.resume_run(...)`. |
| Manual lifecycle primitives | Your own orchestrator is still inside an unsealed run | Call `ns.interrupt(...)` and `ns.checkpoint(...)` before terminal finalization. |

## Policy-Driven Pause

Use a veto for operations that must stop before the act phase. In enforce mode,
`governance_pause_on_veto=True` converts the veto into a paused, unsealed run.

```python
import noesis as ns
from noesis.intuition import IntuitionEvent


class ProductionApproval(ns.DirectedIntuition):
    def advise(self, state: dict) -> IntuitionEvent | None:
        task = str(state.get("task", "")).lower()
        if "production" in task and ("delete" in task or "deploy" in task):
            return self.veto(
                advice="Production side effect requires human approval.",
                target="act",
                rationale="High-risk production changes must be reviewed.",
            )
        return None


ns.set(
    governance_mode="enforce",
    governance_pause_on_veto=True,
)

def deploy_graph(task: str) -> dict[str, str]:
    return {"task": task, "status": "approved-path"}


episode_id = ns.solve(
    "Deploy payment service to production",
    using=deploy_graph,
    intuition=ProductionApproval(),
)
```

When the policy vetoes:

- no `act` event is emitted
- no `terminate` event is emitted
- `final.json` and `manifest.json` are absent until continuation finalizes
- `state.json` records a partial outcome
- a checkpoint is available under the run directory

## Approval Resume Runbook

Use this flow after your approval system has identified a paused run.

```python
import noesis as ns


def latest_checkpoint_id(episode_id: str) -> str:
    events = list(ns.events.read(episode_id))
    checkpoints = [
        event
        for event in events
        if event.get("phase") == "runtime"
        and event.get("event_type") == "run.checkpoint"
    ]
    if not checkpoints:
        raise RuntimeError(f"No checkpoint found for {episode_id}")

    payload = checkpoints[-1].get("payload") or {}
    checkpoint_id = payload.get("checkpoint_id")
    if not isinstance(checkpoint_id, str) or not checkpoint_id:
        raise RuntimeError(f"Checkpoint event for {episode_id} has no checkpoint_id")
    return checkpoint_id


def resume_after_approval(episode_id: str, using) -> str:
    checkpoint_id = latest_checkpoint_id(episode_id)
    return ns.resume_run(
        episode_id,
        checkpoint_id=checkpoint_id,
        using=using,
    )
```

<Note>
Approval must change the condition that caused the pause. For a prepared tool
draft, that means persisting an approved `ToolApprovalDecision`. For a policy
veto, make the approval visible to the policy or continuation path before
calling `resume_run(...)`; otherwise the same veto may recur.
</Note>

## Prepared Tool Approval

Protocol adapters should use the tool invocation contract when the side effect
must be reviewed outside the runtime process.

The durable identity is `run_id + draft_id`:

```python
from noesis.domain.tool_contract import ApprovalDecisionStatus, ToolApprovalDecision
from noesis.infrastructure.tool_invocation.repositories import (
    FileApprovalDecisionRepository,
    FilePreparedInvocationRepository,
)


def approve_pending_draft(*, run_dir, run_id: str, approver_id: str) -> str:
    prepared_repo = FilePreparedInvocationRepository(run_dir=run_dir)
    approval_repo = FileApprovalDecisionRepository(run_dir=run_dir)

    prepared = prepared_repo.load_pending_for_run(run_id=run_id)
    if prepared is None or prepared.draft_id is None:
        raise RuntimeError(f"No pending draft for {run_id}")

    approval_repo.save(
        ToolApprovalDecision(
            decision_id=f"approval:{prepared.draft_id}",
            run_id=prepared.run_id,
            request_id=prepared.request_id,
            candidate_id=prepared.governance.candidate_id,
            draft_id=prepared.draft_id,
            status=ApprovalDecisionStatus.APPROVED,
            reviewed_fingerprint=prepared.payload.request_fingerprint,
            impact_hash=prepared.preflight.impact_hash if prepared.preflight else None,
            approver_id=approver_id,
        )
    )
    return prepared.draft_id
```

After saving approval, call `ns.resume_run(episode_id, checkpoint_id=...)`.
The runtime bridge loads exactly one pending draft for the run and dispatches it
only if the approval binding still matches the prepared payload.

## Operational Checks

Before asking for approval:

- confirm there is a runtime `run.interrupt` event caused by the governance or tool event
- confirm there is a runtime `run.checkpoint` event caused by the interrupt
- inspect `tool_invocations/prepared/*.json` for prepared tool drafts, if applicable
- show reviewers the redacted payload, request fingerprint, impact hash, and policy reason

After approval and resume:

- expect a runtime `run.resume` event
- expect actuation evidence or `tool.execution.*` / `tool.replayed` events
- expect terminal artifacts (`final.json`, `manifest.json`) once continuation completes
- treat repeated `tool.replayed` outcomes as successful idempotent replays, not new dispatches

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `RunSealedError` | The run already has `final.json` and `manifest.json` | Start a new run or move the approval gate before terminal finalization. |
| `CheckpointNotFoundError` | Wrong `checkpoint_id` or wrong run directory | Read the latest `run.checkpoint` event and use its `payload.checkpoint_id`. |
| `CheckpointConsistencyError` mentioning event history | Events before the checkpoint were edited or truncated | Restore the original `events.jsonl` prefix from the checkpointed run. |
| `CheckpointConsistencyError` mentioning state hash | `state.json` changed after checkpoint | Resume from the original state or create a new checkpoint from the new state. |
| `CheckpointConsistencyError` mentioning artifact manifest hash | Manifest presence/content or checkpointed artifacts changed | Restore the checkpointed artifact set; pre-manifest checkpoints hash the artifact set and the event prefix at the checkpoint boundary. |
| `ResumeAdapterRequiredError` | The checkpoint came from a non-minimal adapter run | Pass the original adapter to `resume_run(..., using=...)`. |
| `ResumeAdapterMismatchError` | `using` does not match checkpoint metadata | Resume with the same adapter label/callable used by the paused run. |
| `ApprovalDecisionBindingError` | Approval does not match the reviewed draft | Persist approval with the prepared draft's `request_id`, `reviewed_fingerprint`, and `impact_hash`. |
| `AmbiguousPreparedToolInvocationError` | More than one pending draft exists for one run | Resolve or cancel duplicate drafts before resuming. |
| `UnsupportedToolProtocolError` | Runtime bridge received a non-subprocess draft | Route HTTP/MCP approvals through adapter-specific execution until bridge support is added. |
