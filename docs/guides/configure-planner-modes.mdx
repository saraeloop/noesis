---
title: "Configure planner modes"
description: "How to toggle MetaPlanner vs MinimalPlanner. Governance is a separate config."
---

`planner_mode` selects the planner (`MetaPlanner` vs `MinimalPlanner`). It does **not** turn governance on or off. `governance_mode` (`off` / `audit` / `enforce`) and `governance_pause_on_veto` are independent keys. Default `governance_mode` is `"off"`, so meta planning without an explicit governance mode emits no governance events.

## Understanding planner modes

| Mode | Description | Use when |
| --- | --- | --- |
| `meta` (default) | `MetaPlanner` plus direction search / directives | You want direction events and intuition steering |
| `minimal` | `MinimalPlanner` only (no direction search) | Smoke tests or when you do not need MetaPlanner |

## Setting the planner mode

### Python API

```python
import noesis as ns

ns.set(planner_mode="meta")
ns.set(planner_mode="minimal")

config = ns.get()  # mapping; there is no ns.config()
print(config["planner_mode"])
```

### Environment variable

```bash
export NOESIS_PLANNER=meta
noesis run "my task"

# Or inline
NOESIS_PLANNER=minimal noesis run "my task"
```

### Configuration file

Create a `noesis.toml` in your project root:

```toml noesis.toml
[noesis]
planner_mode = "meta"
runs_dir = "./.noesis/episodes"
```

### Precedence

Configuration is resolved in this order (highest to lowest):

1. `ns.set()` call in code
2. `NOESIS_PLANNER` environment variable
3. `noesis.toml` configuration file
4. Default value (`meta`)

## Meta mode (default)

Meta mode enables `MetaPlanner` and direction events. Governance still needs `governance_mode`:

```python
import noesis as ns

ns.set(planner_mode="meta", governance_mode="enforce")

episode_id = ns.run("Provision staging infrastructure")

events = list(ns.events.read(episode_id))
direction = [e for e in events if e["phase"] == "direction"]
governance = [e for e in events if e["phase"] == "governance"]

print(f"Direction events: {len(direction)}")
print(f"Governance events: {len(governance)}")
```

### What meta mode provides

- **MetaPlanner**: Threads through every episode for structured planning
- **Direction events**: Records directive status (`applied`, `blocked`, `skipped`)
- **Intuition steering handoff**: Carries `risk_level`, `strategy_hints`, `tool_constraints`, and `scrutiny_level` into Direction

`PreActGovernor` and governance events come from `governance_mode`, not from `planner_mode`.

## Minimal mode

Minimal mode skips **direction search**. It does not disable governance.

```python
import noesis as ns

# Default governance_mode is "off", so this run has no governance events
ns.set(planner_mode="minimal")
episode_id = ns.run("Quick sanity check")
assert not any(e["phase"] == "governance" for e in ns.events.read(episode_id))

# Explicit enforce still governs — and can pause — on the minimal planner
class NoopGraph:
    def invoke(self, payload):
        return payload

ns.set(
    planner_mode="minimal",
    governance_mode="enforce",
    governance_pause_on_veto=True,
)
paused_id = ns.solve(
    "Danger operation: delete production database",
    using=NoopGraph(),
    intuition=False,
)
```

### What minimal mode skips

- `MetaPlanner` / direction search
- Direction events from that planner path

### What minimal mode keeps

- The cognitive loop (observe → interpret → plan → act → reflect → learn)
- Event timeline (`events.jsonl`)
- Governance when `governance_mode` is `audit` or `enforce` (`PreActGovernor`)
- Summary artifacts (`summary.json`) on terminal runs

## Inspecting governance metrics

When using meta mode, governance metrics are available in the summary:

```python
import noesis as ns

ns.set(planner_mode="meta")
episode_id = ns.run("Sensitive operation", intuition=True)

summary = ns.summary.read(episode_id)
metrics = summary.get("insight", {}).get("metrics", {})

print(f"Plan revisions: {metrics.get('plan_revisions', 0)}")
print(f"Veto count: {metrics.get('veto_count', 0)}")
print(f"Plan adherence: {metrics.get('plan_adherence', 1.0):.2%}")
print(f"Tool coverage: {metrics.get('tool_coverage', 1.0):.2%}")
```

## Governance decisions

The PreActGovernor can make three decisions:

| Decision | Effect | When it happens |
| --- | --- | --- |
| `allow` | Action proceeds normally | No policy concerns |
| `audit` | Action proceeds, marked for review | Medium-risk operations |
| `veto` | Action blocked | High-risk or policy violations |

## Handling vetoes

Vetoes are emitted by **Governance** (not Direction) and only block actions in `governance_mode="enforce"`:

```python
import noesis as ns

ns.set(planner_mode="meta")
ns.set(governance_mode="enforce")

episode_id = ns.run("DROP TABLE users", intuition=True)
events = list(ns.events.read(episode_id))

governance_veto = next(
    (
        e
        for e in events
        if e["phase"] == "governance" and e.get("payload", {}).get("decision") == "veto"
    ),
    None,
)

if governance_veto:
    print("Governance vetoed the action")
    print(governance_veto["payload"]["rule_id"])
```

If `governance_pause_on_veto=true`, enforce vetoes pause the run with runtime lifecycle events (`run.interrupt`, `run.checkpoint`) instead of immediate termination.

## Switching modes dynamically

You can switch modes between episodes:

```python
import noesis as ns

# Run with full governance
ns.set(planner_mode="meta")
governed_ep = ns.run("Critical operation", intuition=True)

# Run without MetaPlanner (governance still follows governance_mode)
ns.set(planner_mode="minimal")
test_ep = ns.run("Quick test")

# Back to governed mode
ns.set(planner_mode="meta")
another_governed_ep = ns.run("Another critical operation", intuition=True)
```

## CLI usage

Toggle modes from the command line:

```bash
# Meta mode (default)
noesis run "Sensitive task"

# Minimal mode via environment
NOESIS_PLANNER=minimal noesis run "Quick test"
```

## When to use each mode

### Use meta mode for:

- Production workloads that need direction search
- Tasks with intuition steering into Direction
- Runs where you want directive diffs in the trace

### Use minimal mode for:

- Development and testing
- Quick sanity checks
- Benchmarking adapter performance

Governance/veto still requires `governance_mode="enforce"` (and `governance_pause_on_veto=True` to pause instead of seal).

## Troubleshooting

<AccordionGroup>
  <Accordion title="No direction events appearing">
    You're likely in `minimal` mode. Check with:

    ```python
    print(ns.get()["planner_mode"])  # "meta" to emit direction search
    ```

    Set to meta mode: `ns.set(planner_mode="meta")`
  </Accordion>
  
  <Accordion title="Veto not blocking actions">
    Ensure Governance is enforcing:
    
    ```python
    ns.set(planner_mode="meta")
    ns.set(governance_mode="enforce")
    ns.run("task", intuition=True)
    ```

    In `governance_mode="audit"` or `off`, veto-like risk signals can still appear in direction/intuition artifacts, but they do not block actuation.
  </Accordion>
  
  <Accordion title="Governance metrics are zero">
    Set `governance_mode` (and a policy or a goal that hits built-in rules). Meta planner is not sufficient:

    ```python
    ns.set(planner_mode="meta", governance_mode="enforce")
    ns.run("Danger operation: delete production database", intuition=False)
    ```
  </Accordion>
</AccordionGroup>
