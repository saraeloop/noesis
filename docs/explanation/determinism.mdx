Noēsis provides a determinism substrate that enables reproducible episode execution and replay validation. This is essential for debugging, testing, and compliance scenarios.

## Deterministic components

Noēsis includes several deterministic components that can be enabled for reproducibility:

| Component | Purpose | How it works |
| --- | --- | --- |
| **Deterministic clock** | Consistent timestamps | Uses fixed tick intervals instead of wall clock |
| **Deterministic RNG** | Reproducible random values | Seeded random number generator |
| **Deterministic IDs** | Stable identifiers | UUIDv5 based on namespace + content |
| **Canonical JSON** | Byte-identical output | Sorted keys, consistent formatting |

## Episode IDs

Episode IDs use ULID format for sortability and uniqueness:

```
ep_20251108_120000_abc123_def4_s0
│   │        │      │       │   │
│   │        │      │       │   └── seed (s0)
│   │        │      │       └────── entropy (def4)
│   │        │      └────────────── hash (abc123)
│   │        └───────────────────── timestamp (120000)
│   └────────────────────────────── date (20251108)
└────────────────────────────────── prefix (ep_)
```

**ULID properties**:
- Monotonic (sortable by time)
- 48-bit timestamp + 80-bit entropy
- Lexicographically sortable
- URL-safe characters

## Directive and governance IDs

Direction and governance events use deterministic UUIDv5 IDs:

```python
import uuid

# Deterministic ID based on namespace and content
directive_id = uuid.uuid5(
    uuid.NAMESPACE_DNS,
    f"{episode_id}:{phase}:{payload_hash}"
)
```

This ensures:
- Same input produces same ID
- Causal lineage is reproducible
- Replay comparisons are reliable

## Using seeds for reproducibility

Set a seed to get deterministic episode execution:

```python
import noesis as ns

# Set seed for reproducibility
ns.set(seed=42)

# These episodes will have deterministic behavior
ep1 = ns.run("task")

ns.set(seed=42)
ep2 = ns.run("task")

# ep1 and ep2 have matching IDs and behavior
```

## Session-level determinism (clock + RNG)

For stricter reproducibility, inject a deterministic clock and RNG when building a session:

```python
import noesis as ns
from noesis.runtime.session import SessionBuilder
from noesis.runtime.determinism import DeterministicClock, DeterministicRNG

clock = DeterministicClock.from_start("2024-01-15T10:30:00Z", tick_ms=10)
rng = DeterministicRNG(seed=42)

session = (
    SessionBuilder.from_env()
    .with_determinism(clock=clock, rng=rng, episode_timestamp_ms=1705314600000)
    .build()
)

ep = session.run("Draft release notes")
```

This locks timestamps, random numbers, and episode timestamps; the seed and determinism choices are reflected in `summary.json`.

## Replay comparison

Compare episode replays to detect drift:

```python
import noesis as ns
from pathlib import Path


def compare_episodes(ep1_id: str, ep2_id: str) -> dict:
    """Compare two episode executions for drift detection."""
    
    events1 = list(ns.events.read(ep1_id))
    events2 = list(ns.events.read(ep2_id))
    
    diffs = {
        "event_count_match": len(events1) == len(events2),
        "phase_sequence_match": True,
        "payload_diffs": [],
    }
    
    for e1, e2 in zip(events1, events2):
        if e1["phase"] != e2["phase"]:
            diffs["phase_sequence_match"] = False
            break
        
        # Compare payloads (excluding timestamps)
        p1 = {k: v for k, v in e1.get("payload", {}).items() if k != "timestamp"}
        p2 = {k: v for k, v in e2.get("payload", {}).items() if k != "timestamp"}
        
        if p1 != p2:
            diffs["payload_diffs"].append({
                "phase": e1["phase"],
                "diff": {"expected": p1, "actual": p2}
            })
    
    return diffs


# Compare replay
result = compare_episodes("ep_original", "ep_replay")
if result["payload_diffs"]:
    print("Drift detected!")
```

## Golden test suite

Use golden tests to validate deterministic behavior in CI:

```python
import json
from pathlib import Path


def test_golden_episode():
    """Validate episode against golden snapshot."""
    import noesis as ns
    
    # Run with fixed seed
    ns.set(seed=42)
    episode_id = ns.run("Generate test data")
    
    # Load golden snapshot
    golden_path = Path("tests/golden/generate_test_data.json")
    with open(golden_path) as f:
        golden = json.load(f)
    
    # Compare summary
    summary = ns.summary.read(episode_id)
    
    assert summary["metrics"]["success"] == golden["metrics"]["success"]
    assert summary["metrics"]["act_count"] == golden["metrics"]["act_count"]
    
    # Compare event sequence
    events = list(ns.events.read(episode_id))
    assert len(events) == len(golden["events"])
    
    for actual, expected in zip(events, golden["events"]):
        assert actual["phase"] == expected["phase"]
```

## Runtime clock

The `RuntimeClock` provides deterministic timing:

```python
from noesis.runtime.determinism import RuntimeClock

# Deterministic clock with fixed tick interval
clock = RuntimeClock(deterministic=True, tick_interval_ms=10)

# Each call advances by tick_interval
t1 = clock.now()  # 0
t2 = clock.now()  # 10
t3 = clock.now()  # 20

# Real clock for production
real_clock = RuntimeClock(deterministic=False)
```

## Canonical JSON serialization

Noēsis uses canonical JSON for byte-identical output:

```python
from noesis.runtime.determinism import canonical_dumps

data = {"b": 2, "a": 1, "c": [3, 1, 2]}

# Canonical output: sorted keys, consistent formatting
output = canonical_dumps(data)
# '{"a": 1, "b": 2, "c": [3, 1, 2]}'

# Same input always produces same bytes
assert canonical_dumps(data) == canonical_dumps(data)
```

This ensures:
- Manifest hashes are reproducible
- Artifact comparison is reliable
- Git diffs are meaningful

## When to use determinism

<Tip>
**Use deterministic mode for**:
- Unit and integration tests
- Golden test validation
- Debugging specific issues
- Compliance audits requiring reproducibility
</Tip>

<Warning>
**Avoid deterministic mode for**:
- Production workloads (use real timestamps)
- Performance benchmarks
- Security-sensitive operations (predictable IDs)
</Warning>
