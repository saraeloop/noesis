## What

**Noēsis** helps you:

- **Run** episodes (baseline or through an adapter you provide),
- **Direct** them with lightweight, testable policies (a.k.a. _intuition_),
- **Observe** trustworthy **insight** metrics and event streams.

It’s a **small, stable API** you can embed in research code or production pipelines.

## Why

- **Guardrails without rewrites.** Inject patches or veto risky plans before tools run.
- **Deterministic signals.** Insight reports only what we can defend (veto rate, latencies, confidence histogram, alignment).
- **Minimal surface.** Fewer moving parts → easier reasoning, better tests.

## How (mental model)

- **Episode**: a single run (id: `ep_*`).
- **Events**: structured lifecycle records (`start`, `direction`, `insight`, `terminate`, …).
- **Intuition**: a policy class that may `intervene()` (apply a patch) or `veto()` (block).
- **Insight**: post-hoc metrics derived from events (no magic, no placeholders).

## Quick start

### CLI

```bash
# Run without adapters (baseline)
uv run noesis run "hello world"

# List recent episodes (compact table)
uv run noesis list --limit 5

# Snapshot computed insight (JSON)
uv run noesis insight ep_abc123
```

### Python

```python
import noesis as ns

ep = ns.run("demo", intuition=True)
summary = ns.summary.read(ep)
events = list(ns.events.read(ep))
```
