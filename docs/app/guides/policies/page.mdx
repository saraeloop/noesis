# Intuition policies

Intuition is Noēsis shorthand for the policy classes that observe episode state and decide whether to
intervene or veto. Policies are regular Python classes—easy to test, log, and ship.

## Anatomy of a policy

```python filename="intuition.py"
from noesis import intuition, events


class GuardRail(intuition.Policy):
    def intervene(self, event: events.BaseEvent):
        if event.type == "direction" and "wire transfer" in event.payload.text.lower():
            return intuition.Patch(
                reason="Financial transfers must be reviewed manually.",
                replacement="Let's switch to manual verification before continuing."
            )

    def veto(self, event: events.BaseEvent):
        if event.type == "insight" and event.payload.risk_score > 0.9:
            return intuition.Veto(reason="Risk score too high for autonomous execution.")
```

## Wiring policies

```bash filename="terminal"
uv run noesis run "plan next steps" \
  --adapter baseline \
  --intuition GuardRail
```

Pass the dotted path to your policy class—Noēsis loads it and evaluates every event.

<Steps>

### 1. Observe events

Policies receive every lifecycle event. Use event types to scope decisions and log metadata.

### 2. Return a patch or veto

`Patch` mutates the episode context; `Veto` halts execution. Both require a human-readable reason for auditing.

### 3. Test in isolation

Import your policy class in unit tests and feed synthetic events to assert interventions.

</Steps>

<Callout type="info" emoji="🛠️">
Policies are pure Python—no hidden thread pools or async requirements. Keep state on the class if you need short-term memory.
</Callout>

## Learning from policy outcomes

Noēsis records every directional decision and runs the learn loop after an episode finishes. When recurring signals appear (for example, repeated vetoes), the framework proposes a policy adjustment and scores it with a heuristic.

- Proposals include the target (e.g. `direction_min_confidence`), score function, confidence, and a revert handle when auto-applied.
- Configure the auto-apply gate via `learn_auto_apply_min_confidence` and `learn_auto_apply_min_successes`; the default requires three successful high-confidence triggers before applying.
- Switching `learn_mode` to `"apply"` lets Noēsis promote approved proposals automatically while still emitting a diff and revert handle inside `learn.jsonl` and the policy snapshot.

<Callout type="warning" emoji="⚙️">
Policies never mutate `state.json` directly. They emit proposals; the core loop applies them only after the safety gate fires.
</Callout>
