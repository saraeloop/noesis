# Incident Triage Dashboard

> A Gradio app that walks through observe → interpret → plan → act → reflect → learn with production guardrails, human approvals, and learn proposals.

## TL;DR demo

```bash filename="terminal"
uv pip install "noesis[ui]"
uv run python -m examples.incident_triage.gradio_app
```

Pick an incident prompt, dial in your safety knobs, press **Run Noēsis**, and inspect the artefacts (events, summary, learn proposals) that drop into `runs/<episode>/`.

## What ships in the example

| Module | Purpose | Production swap |
| ------ | ------- | ---------------- |
| `examples.incident_triage.app_incident_triage` | Deterministic callable that simulates Detector → Responder → Reviewer. | Replace `_detector` with Prometheus/Datadog queries, `_responder` with LangGraph plan generator, `_reviewer` with Slack/ServiceNow approval. |
| `examples.incident_triage.prod_guard.ProdGuardPolicy` | Directed intuition that vetoes destructive ops, scopes global actions, and hints best practices. | Encode your organisation’s guardrails (change windows, runbooks, RBAC checks). |
| `examples.incident_triage.gradio_app` | Gradio UI that shows timeline, metrics lattice, interventions, and learn proposals. | Keep the shell; extend the helpers to surface service-specific visuals. |
| `examples.incident_triage.streamlit_app` | Optional Streamlit port if your team prefers Streamlit for internal tooling. | Same integration points as the Gradio app. |

All nodes are deterministic so reviewers can run the demo without LLM keys. Swap the TODOs for actual service clients to turn this into a production control room.

## Key safety knobs

| Setting | Description |
| ------- | ----------- |
| **Intuition mode** | `advisory`, `interventive`, or `hybrid` maps directly to the Noēsis intuition surface. |
| **Direction min confidence** | Baseline confidence required before the agent executes an action. |
| **Learn mode** | `off`, `record`, or `apply-safely` controls whether learn proposals are only logged or auto-applied. |
| **High-risk toggle** | Sends a `risk=high` tag to the policy, triggering a hard veto path (great for red-team demos). |

Every run produces:

- A dense timeline (`events.jsonl`) with phases, agent IDs, advice, status.
- `summary.json` with success metrics, latencies, and learn proposal counts.
- Optional learn artefacts in `runs/<episode>/learn/*.jsonl`.

## Human-in-the-loop illustration

The responder emits a proposed action (e.g., “trigger_rollback”). The reviewer node enforces the rule “high risk + no canary scope ⇒ needs_scope”. When the DirectedIntuition adds `requires_approval=True`, the Gradio UI highlights the intervention and the action status becomes “awaiting approval”.

To simulate an approval loop:

1. Run the app with a high-risk incident so the policy vetoes or patches the plan.
2. Edit `app_incident_triage._reviewer` to flip the status to `approved`.
3. Run again; you’ll see improved metrics (shorter `time_to_first_action_ms`, reduced `veto_rate`) in the summary.

In production you’d wire the reviewer to Slack/Jira/ServiceNow, flip the approval, and re-trigger the graph.

## Replace the mocks with reality

- **Signals** → swap `_detector` for PromQL / Datadog / New Relic. Drop the results into `state.signals`.
- **Plan generator** → wrap your LangGraph graph (LLM + retrieval, deploy diffs, feature flag context).
- **Executor** → integrate a dry-run + approval gate (Kubernetes, Terraform, feature flag toggles).
- **Runbooks** → attach doc links in the `state.notes` or ask the policy to enforce them.
- **Policy** → integrate your change calendar, runbook heuristics, and PII detectors inside `ProdGuardPolicy`.

The demo is intentionally opinionated so you don’t have to guess where to hook in.

## Optional: Streamlit + static artefacts

```bash filename="terminal"
uv run streamlit run examples/incident_triage/streamlit_app.py
```

Prefer static exploration? Run the app once, then share the resulting `runs/<episode>/` folder with teammates. The Streamlit app can read and replay existing episodes without rerunning the loop.
